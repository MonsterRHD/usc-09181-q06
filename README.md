# 多币种出行资金管家

面向国际医疗与出差持卡人的跨境卡交易资金服务：接收刷卡预授权、撤销、离线补传清算、商户补扣与汇率快照，按持卡人授权范围计算多币种可用余额与费用，并把每一次展示的换算依据固定下来。状态落盘，服务重启后完全恢复。

## 防重复扣款的三道幂等

1. **网络事件 ID**：`event_id` 全局唯一，重放返回 `duplicate`，不动账、不重复通知。
2. **商户订单号**：同账户 + 商户 + `merchant_ref` 的授权只认第一笔，商户换流水号重试、跨午夜重试一律拒绝；撤销报文用 `REV:` 前缀单独去重。
3. **授权链接**：一笔预授权只能清算一次。离线终端补传/网络重发（无论是否换 `event_id`）在 `settled` 后一律拒绝；部分撤销先累计，清算额不得超过“授权额−已撤销额”。

## 授权、清算与补扣

- 授权按**当时已采纳汇率快照**折算本币，连同预计外币手续费一并冻结；校验单笔限额（原币与本币双口径）与 `余额 − 冻结`。
- 清算采用**当前已采纳**快照（允许正常汇率更新），先释放全部剩余冻结，再多退少补；手续费按实际清算额重算。
- 清算前（部分）撤销按比例解冻；清算后（部分）退货连同对应手续费退回。
- 商户补扣（酒店 mini-bar 等）累计额受持卡人授权范围约束：`累计补扣 ≤ 清算额 × rebill_bps`（默认 20%），无冻结、直接扣款。

## 汇率与人工复核

- 汇率以 6 位定点数解析，快照不可变。新快照相对当前已采纳汇率偏离超过阈值（默认 2%，200bps）→ `pending_review`，**绝不静默采用**；待审期间所有授权/清算/展示继续使用上一张已采纳快照，无可用汇率则拒绝交易。
- 复核仅两个动作：`approve`（采纳）/ `reject`（驳回，永不采用），全程审计。
- 每次展示换算都生成不可变 `DisplayBasis`：源金额、快照 ID、汇率、换算结果；历史展示不会被后续汇率更新改变。账务流水中每笔外币记录实际使用的 `fx_snapshot_id` 与汇率。

## 争议（只追加）

- 客户对已入账交易发起争议；客服只能 `POST /v1/disputes/{id}/conclusions` **追加**调查结论，系统不提供任何修改/删除交易或记录的接口。
- 裁决 `won` 自动生成冲正流水（本金 + 手续费全额返还），`lost` 仅关闭；每条结论、裁决与冲正均留痕。

## 合规与可观测

- 监管最小记录：只保存掩码卡号（如 `6225********1234`），客户明细中商户名同样脱敏；不落完整 PAN。
- 账务流水与审计记录均为**哈希链**，`GET /v1/accounts/{id}/verify` 校验完整性，任何追溯改账都会断链。
- 通知按 `类型|event_id` 去重计数；按账户导出（`GET /v1/accounts/{id}/export`，需 `X-Role: agent`）包含脱敏事件、流水、争议、通知计数与链校验结果，导出动作本身入审计链。

## HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v1/accounts` | 开户（必须提供掩码卡、本币、初始余额） |
| GET  | `/v1/accounts/{id}/balance` | 余额/冻结/可用 |
| GET  | `/v1/accounts/{id}/details` | 客户脱敏明细（含历史快照与本币金额） |
| GET  | `/v1/accounts/{id}/notifications` | 通知列表（计数用） |
| POST | `/v1/accounts/{id}/conversions` | 固定一次展示的换算依据 |
| POST | `/v1/accounts/{id}/disputes` | 客户发起争议 |
| GET  | `/v1/accounts/{id}/export` | 监管导出（agent） |
| GET  | `/v1/accounts/{id}/verify` | 哈希链校验 |
| POST | `/v1/events` | 上送 auth/reversal/presentment/rebill |
| POST | `/v1/fx/snapshots` | 汇率快照（异常返回 202 pending_review） |
| GET  | `/v1/fx/pending` | 待人工复核快照 |
| POST | `/v1/fx/{id}/review` | 复核 `{"decision":"approve|reject"}`（agent） |
| GET  | `/v1/disputes/{id}` | 争议详情（含全部追加记录） |
| POST | `/v1/disputes/{id}/conclusions` | 客服追加调查结论（agent） |
| POST | `/v1/disputes/{id}/resolve` | 裁决 `{"decision":"won|lost"}`（agent） |

客服接口需请求头 `X-Role: agent`。事件金额一律为币种最小单位整数（JPY 0 位小数，其余 2 位），时间用 RFC3339。

## 运行与测试

```bash
go test ./...              # 含现场检查全链路场景与重启恢复
PORT=8080 DATA_DIR=./data go run .
```

`DATA_DIR` 下 `state.json` 为全量状态，写入走临时文件 + 原子 rename；启动时加载，现场检查中重启服务后余额、冻结、争议状态、通知计数与待审汇率均保持不变。

## 现场检查场景（见 TestInspectionScenario）

预授权 100 EUR（7.80，冻结 788 CNY）→ 同事件重放/商户换号重试/跨午夜重试全部防住（通知仍为 1 条）→ 汇率正常更新到 7.90 → 异常快照 8.50 挂起 → **重启服务**（冻结与待审汇率不变）→ 离线补传按 7.90 清算 798（补传重发/换号再传均拒绝）→ **再次重启** → 客户争议、客服两次追加结论、胜诉全额冲正回 100000 → 通知恰好 4 条 → 哈希链完整、明细脱敏且记录清算实际快照。
