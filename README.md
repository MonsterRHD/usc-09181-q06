# 多币种出行资金管家

面向国际医疗与出差人员的跨境卡交易资金管家：接收**刷卡、预授权、撤销、补扣、离线补传与汇率快照**，
在**持卡人授权范围**内计算可用余额与费用，把每一次展示的换算依据固定下来；跨午夜交易、离线终端补传、
部分撤销与商户重试均不会造成重复扣款；异常汇率进入人工复核，绝不静默采用。

## 领域规则

| 主题 | 规则 |
| --- | --- |
| 预授权/刷卡 | 批准即按**授权时点的汇率快照**冻结 `消费额+手续费`，可用余额 = 授信额度 − 在冻 − 已出账 |
| 撤销 | 支持部分撤销；清算前按授权快照比例**释放冻结**，清算后按清算快照比例**退还**；`ReversalRRN` 去重 |
| 清算/补扣 | 按**清算时点的有效汇率**重算最终账单，与冻结差额自动补扣或释放；一笔 RRN 只入账一次 |
| 离线补传 | 有在先授权则按 RRN 命中原笔（允许跨午夜、授权过期后迟到）；无授权的 force post 直接入账并完整留痕 |
| 防重复扣款 | 幂等键 = `卡号 + RRN`；商户重试、重复批次、跨午夜补送、撤销重放全部命中原笔，另记 `DuplicateRejected` 审计事件 |
| 汇率快照 | 每次换算把快照（ID/汇率/时间/来源）**值拷贝进事件**；历史明细的授权口径与清算口径永久固定、互不改写 |
| 异常汇率 | 非正数、超过 24h、相对有效汇率偏离 >5% → 隔离并写 `FXRateQuarantined`，等待员工人工批准/驳回；隔离期交易沿用上一有效汇率 |
| 无汇率 | 不编造汇率：按 1:0 临时口径占额，明细标记 `pending_rate` |
| 争议 | 客户发起；客服只能**追加**备注与一次性终局结论（胜诉/部分胜诉产生退款），结论后争议只读 |
| 脱敏 | 原始 PAN 永不落盘，登记前即脱敏为 `453201******0366` |
| 最小记录 | 事件只保留监管必要字段；支持员工按账户导出该账户的 JSONL 事件流（全局汇率事件不混入） |
| RBAC | customer：本人明细/发起争议；agent：查看、追加调查结论；admin：导出、汇率人工复核 |
| 通知 | 通知本身是事件，落盘后才发送一次；**重启重放只恢复计数，不会重发** |

金额全部使用币种最小单位的整数，汇率以 1e6 倍率整数表示（`big.Int` 换算、half-up 取整），全链路无浮点。

## 架构：事件溯源 + 物化视图

```
命令(Authorize/Presentment/Reverse/ReceiveFXRate/OpenDispute…)
        │  校验：幂等键 / 授权范围 / 余额 / 汇率异常隔离
        ▼
只追加事件流（Store：FileStore=JSONL，MemoryStore=测试）
        │  append 后立即 apply(live=true)：更新余额、在冻、幂等索引；通知仅此处触发一次
        ▼
State 物化视图（账户/卡片/交易/争议/汇率/隔离队列/通知计数）
重启 = 重放全部事件（live=false，不发通知），FileStore 落盘故跨进程恢复
```

事件类型见 `travelmoney/events.go`，资金状态迁移见 `travelmoney/state.go`，命令与查询见
`travelmoney/service.go`、`travelmoney/service_support.go`。

## 现场检查剧本（`TestOnSiteScenario_PreauthOfflineClearFXUpdateRestart`）

同一笔交易依次经历：跨午夜预授权（23:50 终端时间）→ 商户重试（幂等命中）→
次日 00:10 离线终端补传清算 → 重复批次再送（拦截）→ 汇率 1.10 更新为 1.12 →
客户争议、客服追加备注与全额退款结论 → **关闭并重启服务**。断言覆盖：

- 余额三段一致：在冻 11000 → 已出账 11000/在冻 0 → 争议退款后回到额度满额；
- 历史明细授权与清算均钉住 `fx-1`（汇率 1.10），新汇率不改写展示依据；
- 争议状态 `concluded`、备注与结论各一条且终局不可改；
- 通知始终 4 条，重启后计数不变、**重放零重发**；
- 重启后 RRN 幂等索引仍生效，重复请款仍被拦截、不产生二次扣款。

其余测试覆盖：部分/清算后撤销、酒店补扣、无授权 force post、过期授权后迟到补传、
异常汇率三类隔离与人工批准/驳回、授权范围（MCC/国家/单笔/日累计）、脱敏与按账户导出。

## 运行

```bash
go test ./...        # 全部领域测试
go run .             # 健康检查服务（:8080/health）
```

`travelmoney` 包是无外部依赖的领域内核，`Store`/`Notifier` 为接口，可直接接入 HTTP/gRPC 适配层。
